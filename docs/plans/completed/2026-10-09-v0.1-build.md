## Decision log

| Decision | Why | Rejected alternative |
|---|---|---|
| Wardrobe = folder of YAML + photos, maintained by the owner | Owner wants to set it up once and edit occasionally; no website | Gmail API ingestion (fragile tokens, broad access); forwarding to Cloudflare email (needs a domain) |
| Self-host on Arch behind Tailscale Funnel | Owner's always-on machine; Funnel gives public HTTPS without a domain | Tailnet-only (ChatGPT/Claude connect from their cloud and can't reach it); Cloudflare Workers |
| Python + official MCP SDK v2 (`MCPServer`, built-in `Apps`) | Mature imaging (Pillow), SDK has MCP Apps and the OAuth server | TypeScript on Workers |
| Server narrows candidates, model chooses from a contact sheet | Taste needs the photos; one image is cheaper than one per item | Server-side outfit generation |
| `show_outfit` returns card + image + link | Client rendering on iPhone unknown | Betting on one method |
| Photos in result `_meta` as data URIs | No CSP domains needed; hidden from the model | URLs in `structuredContent` (needs CSP, visible to the model) |
| Stateless MCP over HTTP | Restarts of a home server must not break clients | Session-based streamable HTTP |
| Single-user OAuth with a passphrase | Clients expect OAuth for public endpoints; simplest safe option | Secret path token (leaks via URL) |
| Location via iOS Shortcut on app open, tailnet-only endpoint | Zero effort, and location never touches the public side | Asking the model; IP geolocation (requests come from the client's cloud) |
| MET Norway fallback | Open-Meteo rate-limited the build machine's IP | Single provider |
